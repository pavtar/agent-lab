# Roadmap рабочих агентов

Цель roadmap — развивать агентов постепенно, не смешивая архитектуру и сложные интеграции в один большой шаг.

## Где лежат паспорта

- **Портфель первых запусков** — каталог `agents/<имя>/` (карточки в `Company OS/Agents/`).
- **Черновики** — каталог `agents/draft/<имя>/`: паспорт есть, но **первый полезный результат в рабочем цикле ещё не закреплён**; в Obsidian карточки лежат в `Company OS/Agents/Draft/`, чтобы не путать с готовыми к ежедневному использованию.

## Текущий статус

### Готово для первых запусков (`agents/`)

- `metrika-web-analyst` — есть SDK-запуск, API Яндекс.Метрики, первый отчёт и сохранение в Obsidian.
- `spreadsheet-maker` — есть паспорт, skill для `.xlsx`, методичка в `skills/excel-workbook-generation/guide/`, первый проверенный файл и решение, что SDK пока не нужен.
- `brand-presentation-maker` — есть паспорт, skill, генератор в `tools/uplab-slide-generator/` и проверенная генерация `.pptx`.
- `toyota-kata-coach` — есть паспорт, skill Toyota Kata и первый сценарий `manager_training`.
- `process-architect` — есть паспорт, skill `business-process-mapping`, база знаний по BPM и VSM и сценарии.

### Черновики (`agents/draft/`)

| Агент | Заметка |
| ----- | ------- |
| `meeting-secretary` | Паспорт готов; нужен формат входного транскрипта и первый реальный протокол. |
| `business-system-analyst` | Паспорт готов; нужен шаблон требований и первый BRD/ТЗ. |
| `finance-director` | Только после плана безопасности и источников данных. |

### Следующий фокус

1. `toyota-kata-coach` — провести первый тренажёр руководителя по Coaching Kata.
2. `process-architect` — провести первый реальный разбор процесса Uplab по сценарию `process_assessment` или `as_is_map`.
3. `brand-presentation-maker` — довести до первого реального пользовательского сценария и инструкции для коллег.
4. `metrika-web-analyst` — улучшить еженедельный отчёт: бизнес-цели, конверсии и регулярный playbook.
5. `spreadsheet-maker` — протестировать на реальной таблице для команды.
6. Вынести из **draft**: `meeting-secretary` или `business-system-analyst` — после первого успешного запуска перенести паспорт в `agents/` и карточку в `Company OS/Agents/`.

## Как запускать развитие агента

Для каждого агента используем одинаковый цикл:

1. Plan mode: определить первый полезный результат, входные данные и критерии качества.
2. Проверить или обновить паспорт агента: `README.md`, `prompt.md`, `config.example.json`, `eval-checklist.md`.
3. Сделать первый ручной запуск через Cursor Agent или SDK.
4. Проверить результат по `eval-checklist.md`.
5. Обновить карточку агента в `../Company OS/Agents/` или `../Company OS/Agents/Draft/`, если изменился способ запуска, сценарии, ограничения или статус.
6. Записать выводы в Obsidian или `docs/agent-log.md`.
7. Решить, нужна ли автоматизация через SDK.

## Что не делать сразу

- Не подключать финансовые и CRM-данные без отдельного плана безопасности.
- Не пытаться сделать презентации, таблицы и финансы одним универсальным агентом.
- Не смешивать фирменные инструкции, API-код и отчёты в одной папке.
