# Roadmap рабочих агентов

Цель roadmap — развивать агентов постепенно, не смешивая архитектуру и сложные интеграции в один большой шаг.

## Порядок внедрения

1. `metrika-web-analyst` — уже есть API, данные и первый отчёт.
2. `meeting-secretary` — быстро даёт пользу: протоколы, решения, задачи.
3. `business-system-analyst` — помогает формулировать требования для новых проектов и агентов.
4. `brand-presentation-maker` — требует фирменную документацию и правила формата.
5. `spreadsheet-maker` — требует шаблоны таблиц и проверки структуры.
6. `finance-director` — позже, потому что нужны точные источники данных и контроль расчётов.

## Портфель агентов


| Агент                      | Первый полезный результат               | Следующий шаг                             |
| -------------------------- | --------------------------------------- | ----------------------------------------- |
| `metrika-web-analyst`      | Еженедельный отчёт по Метрике и SEO     | Выбрать бизнес-цели и добавить SEO-данные |
| `meeting-secretary`        | Протокол встречи с решениями и задачами | Определить формат входного транскрипта    |
| `business-system-analyst`  | BRD, ТЗ или карта процесса              | Собрать шаблон требований                 |
| `brand-presentation-maker` | Черновик презентации в фирменном стиле  | Подключить папку бренд-документации       |
| `spreadsheet-maker`        | Таблица по ТЗ или шаблону               | Подключить папку документации по таблицам |
| `finance-director`         | Управленческий финансовый отчёт         | Определить источники финансовых данных    |


## Как запускать развитие агента

Для каждого агента:

1. Заполнить `agents/<agent>/README.md`.
2. Описать первый prompt в `prompt.md`.
3. Заполнить `config.example.json`.
4. Создать `eval-checklist.md`.
5. Сделать первый ручной запуск через Cursor Agent или SDK.
6. По результату решить, нужна ли автоматизация через SDK.

## Что не делать сразу

- Не подключать финансовые и CRM-данные без отдельного плана безопасности.
- Не пытаться сделать презентации, таблицы и финансы одним универсальным агентом.
- Не смешивать фирменные инструкции, API-код и отчёты в одной папке.
