## Что это за репозиторий (простыми словами)

Это **учебный «песочница»-проект** для первых опытов с **интеллектуальными агентами Cursor** (программы, которые по заданию смотрят код и тексты и отвечают или предлагают правки).

**Главная идея:** научиться безопасно ставить задачи агенту — сначала только **чтение и объяснение**, потом уже **предложения в виде отдельного запроса на изменение** (Pull Request), который человек проверяет руками.

**Что лежит внутри:**


| Часть                                   | Зачем                                                                                                                                                                                                                        |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Корневой `README.md`**                | Описание проекта, как подготовить ключ, как запустить локального и «облачного» агента, базовые правила безопасности.                                                                                                         |
| `**scripts/local-repo-summarizer.mjs**` | Сценарий **локального** агента: он работает с копией проекта на вашей машине, получает строгую инструкцию **ничего не менять**, только изучить и объяснить. После работы **дописывает запись в журнал** `docs/agent-log.md`. |
| `**scripts/cloud-readme-pr.mjs`**       | Сценарий **облачного** агента: подключается к **уже выложенному на GitHub** репозиторию и может **улучшить `README.md` и оформить это как Pull Request** для проверки человеком.                                             |
| `**docs/tasks.md`**                     | Черновой список учебных задач для агентов и напоминание, как формулировать задачу (цель, что можно/нельзя, критерий готовности).                                                                                             |
| `**docs/agent-log.md`**                 | Журнал запусков — сюда скрипты подставляют время, идентификаторы запуска и краткий итог.                                                                                                                                     |
| `**docs/agent-card-template.md`**       | Шаблон «карточки» агента (цель, входы, разрешённые и запрещённые действия) — удобно для Obsidian или внутреннего учёта.                                                                                                      |
| `**package.json**`                      | Настройки Node-проекта и команды вроде `agent:local`, `agent:cloud-pr`, `check` (проверка синтаксиса скриптов).                                                                                                              |
| `**.env.example**`                      | Пример переменных: ключ Cursor и при необходимости URL репозитория на GitHub; **настоящие секреты в репозиторий не кладут** (в `.gitignore` указаны `node_modules/` и `.env`).                                               |


То есть репозиторий — это не готовый продукт для пользователей, а **набор инструкций, скриптов и документов**, чтобы пошагово попробовать агентов Cursor с **минимальным риском**: сначала только анализ, потом — изменения через PR.

## Что это за репозиторий

Это **учебная песочница** под названием **agent-lab**. Она нужна, чтобы **аккуратно попробовать умных помощников (агентов) от Cursor** на реальном небольшом проекте — с понятными правилами и ограничениями.

**По смыслу здесь три слоя:**

1. **Два готовых «сценария» (скрипта на Node.js)**
  - **Локальный агент** — смотрит содержимое репозитория и **описывает структуру** (по задумке — только чтение, без правок кода).  
  - **Облачный агент** — при настройке связи с GitHub может **подготовить изменения в `README` и оформить это как Pull Request** (то есть вы сами потом смотрите и решаете — принимать или нет).
2. **Документы в папке `docs/`**
  - **Список задач** для агентов (`tasks.md`).  
  - **Журнал запусков** (`agent-log.md`) — чтобы было видно, что уже пробовали.  
  - **Шаблон карточки агента** для Obsidian — чтобы однотипно описывать эксперименты.
3. **Техническая обвязка**
  - Файл `package.json` описывает проект и команды вроде проверки скриптов и запуска агентов.  
  - Для работы с Cursor предусмотрен **ключ API** (в README и в примере `.env.example` объясняется, что его нельзя светить в репозитории).  
  - В README прописаны **правила безопасности**: сначала задачи на чтение и анализ, критичные изменения — через Pull Request.

**Итог одной фразой:** это не «продукт для клиентов», а **тренажёр для команды**, чтобы понять, как ставить задачи агентам, где риски, и как документировать опыты — с минимальным ущербом, если что‑то пойдёт не так.
