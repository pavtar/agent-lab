# toyota-kata-coach

Коуч по методологии Toyota Kata для руководителя и команды.

## Задача

Помогать руководителю применять Toyota Kata в управлении: формулировать challenge, current condition, target condition, препятствия и следующий эксперимент через коучинговые вопросы.

## Первый сценарий

`manager_training` — тренажёр для руководителя.

Агент даёт короткую рабочую ситуацию, просит руководителя сформулировать коучинговый вопрос, оценивает вопрос и помогает переписать его так, чтобы он развивал мышление сотрудника, а не подсказывал готовое решение.

## Сценарии развития

- `kata_assistant` — справочный помощник по всей Toyota Kata для новичков.
- `manager_training` — тренажёр коучинговых вопросов для руководителя.
- `weekly_coaching` — еженедельный коучинг-цикл по 5 вопросам Toyota Kata и Карте событий ученика.
- `problem_improvement` — Problem Improvement Canvas для разбора бизнес-проблемы через challenge, current condition, target condition, obstacles, next experiment.
- `team_playbook` — Markdown-playbook внедрения Toyota Kata в регулярный менеджмент конкретной команды.

## Быстрый запуск в Cursor Agent

Откройте новый чат Cursor Agent и вставьте:

```text
Работай как агент toyota-kata-coach.
Используй инструкции из agents/toyota-kata-coach/prompt.md.
Сценарий: kata_assistant.

Мой вопрос:
Мне нужен совет по Toyota Kata. С чего начать внедрение в команде руководителей?
```

Для другого режима замените сценарий на `manager_training`, `weekly_coaching`, `problem_improvement` или `team_playbook`.

## Сценарий kata_assistant

`kata_assistant` — входная дверь для руководителей, которые только начинают практиковать Ката-менеджмент и Ката-коучинг.

Результат сценария:

- короткая консультация по методологии;
- объяснение терминов Toyota Kata;
- навигация по базе знаний;
- рекомендация следующего сценария агента.

## Ритм weekly_coaching

В Uplab базовый ритм коучинга — раз в неделю. Это адаптация под управленческую реальность: между встречами ученик должен провести маленький эксперимент или наблюдение, а на следующей встрече сравнить ожидание и факт.

Еженедельная сессия не должна превращаться в статус-митинг. Если за неделю не было проверяемого шага, агент помогает выбрать маленький эксперимент до следующей недели.

## Сценарий team_playbook

`team_playbook` помогает руководителю запустить Toyota Kata в команде на 4-6 недель.

Результат сценария — Markdown-playbook:

- цель внедрения;
- команда, процесс и границы пилота;
- роли: sponsor, coach, learner, second coach;
- недельный ритм;
- артефакты: Карта событий, PDCA, список препятствий;
- первый пилот и критерии успеха;
- риски внедрения;
- действия на ближайшую неделю.

## Сценарий problem_improvement

`problem_improvement` помогает руководителю разобрать конкретную бизнес-проблему без преждевременного перехода к готовому решению.

Результат сценария — Markdown Problem Improvement Canvas:

- краткое описание проблемы;
- challenge или направление;
- current condition: факты, метрики, наблюдения, неизвестные зоны;
- target condition на ближайший горизонт;
- obstacles;
- one obstacle now;
- next experiment: гипотеза, шаг, ожидание, срок проверки;
- что нужно узнать до следующего цикла;
- риск преждевременного перехода к решению.

## Когда нужен SDK

Для первой версии SDK не нужен: агент запускается вручную в Cursor Agent, потому что тренировка интерактивная.

SDK понадобится позже, если нужно регулярно сохранять сессии в Obsidian, вести историю практики руководителя или запускать еженедельный coaching routine по расписанию.

## Первый результат

Короткая тренировочная сессия из 3-5 раундов:

- ситуация;
- вопрос руководителя;
- оценка вопроса;
- улучшенная формулировка;
- итоговый разбор;
- практика на завтра.

## Входные данные

- Роль руководителя.
- Контекст команды или процесса.
- Сценарий тренировки, по умолчанию `manager_training`.
- Уровень сложности: beginner, normal или hard.

## Выход

Текстовая коучинговая сессия в чате Cursor Agent. Если пользователь попросит сохранить результат, агент готовит Markdown-заметку для Obsidian вручную.
