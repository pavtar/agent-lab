# Uplab Slide Generator — Инструкция для пользователей

## Введение

### Что это

**Uplab Slide Generator** — программа на Python: текст презентации лежит в **Markdown**, на выходе — файл **PowerPoint (.pptx)** в фирменном стиле Uplab.

### Как мы предлагаем работать

Мы исходим из того, что **всё делаете вместе с ИИ-агентом** (Cursor, Claude Code и т.п.): он читает правила, пишет и правит Markdown, при необходимости ставит зависимости и **сам запускает генерацию**. Вам **ничего не нужно вводить в терминале** — только общаться с агентом и открывать готовый `.pptx`. Терминал и команды ниже нужны самому агенту (или вам только если решите обойтись без агента).

**Что у вас есть в пакете**


| Файл / папка                              | Зачем                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------ |
| `**AGENT_RULES.md`**                      | Главная инструкция **для агента**: какие бывают слайды, как оформлять Markdown |
| `**USAGE.md`** (этот файл)                | Для вас: вводная, команды, справка по формату (при желании — тоже для агента)  |
| `generate.py`, `requirements.txt`, `src/` | То, что агент запускает и при необходимости чинит                              |
| `templates/`, `assets/`                   | Шаблон PPTX и логотипы — агент подставляет пути, вам трогать не нужно          |
| `examples/*.md`                           | Образцы и мастер-контент для разных задач                                      |


**Дальнейший цикл:** вы формулируете тему, клиента, тезисы → агент собирает или правит ваш `.md` → вы просите **сгенерировать слайды** — агент сам выполнит нужные команды → вы открываете `.pptx` в PowerPoint или Google Slides и при необходимости вставляете картинки вручную.

### Промпт для первого запуска с агентом

Скопируйте в чат с агентом **целиком** (папка проекта уже открыта как workspace):

```
Ты работаешь с Uplab Slide Generator в этой папке. Прочитай AGENT_RULES.md и в USAGE.md раздел «Что выполняет агент (команды)». Установи зависимости: pip install -r requirements.txt. Запусти тестовую генерацию: python generate.py examples/content_tkp.md -o result.pptx. Напиши полный путь к result.pptx и кратко, сколько слайдов получилось.
```

Когда тест прошёл, для **своей** презентации пишите агенту, например: *«Собери КП для клиента X по структуре как в examples/content_tkp.md, сохрани в my_kp.md и сгенерируй pptx»* — агент должен сам вызвать `python generate.py my_kp.md -o …`.

## Что выполняет агент (команды)

Генератор — это скрипт на Python: кто-то должен один раз поставить библиотеки и вызывать `generate.py`. **В типичном сценарии это делает агент**, а не вы.

Если вы **без агента** (или агент просит «выполните сами»), в терминале из папки проекта:

```bash
pip install -r requirements.txt
python generate.py examples/content_tkp.md -o result.pptx
```

По умолчанию подставляется шаблон `templates/Шаблон для презентации.pptx`.

## Конвенция мастеров

Рекомендуемый подход: один визуальный PPTX-шаблон + один универсальный мастер + узкие пресеты под сценарии.

- **Один PPTX-мастер:** `templates/Шаблон для презентации.pptx`
- **Основной мастер контента:** `examples/master_universal.md`

Правила именования:

- **Контент-файлы:** `content_<topic>.md` (например, `content_q2_sales.md`)
- **Готовые PPTX:** `output_<topic>.pptx` (например, `output_q2_sales.pptx`)
- **По умолчанию:** стартовать с `examples/master_universal.md`

Пример запуска:

```bash
python generate.py examples/master_universal.md -o output_universal.pptx
```

## Формат Markdown-файла

### Frontmatter (опционально)

```yaml
---
template: templates/Шаблон для презентации.pptx
output: result.pptx
breadcrumb: "Uplab × Клиент"
---
```


| Поле         | Описание                                                        |
| ------------ | --------------------------------------------------------------- |
| `template`   | Путь к PPTX-шаблону                                             |
| `output`     | Путь для сохранения результата                                  |
| `breadcrumb` | Постоянный подзаголовок на каждом слайде (кроме cover/contacts) |


CLI-флаги `-t` и `-o` имеют приоритет над frontmatter.

### Слайды

Каждый слайд начинается с `# slide_type`. Затем `## Заголовок` и содержимое.

---

## 16 типов слайдов

### 1. cover — Обложка

```markdown
# cover
## Разработка корпоративного сайта для CHINT
Подзаголовок (опционально)
```

### 2. section — Разделитель

```markdown
# section
## Бюджет и сроки реализации
```

### 3. stats — Статистика

Большие числа в правой половине, описание слева снизу.

```markdown
# stats
## Дизайн и разработка для крупного бизнеса
Описание компании или контекст (появится внизу слева).

- 600+ | реализованных проектов
- 100+ | сотрудников
- 16 | лет на рынке
- 90+ | наград
```

Формат элемента: `- ЗНАЧЕНИЕ | описание`

### 4. text — Текстовый слайд

```markdown
# text
## Заголовок
Любой текстовый контент.
- Поддерживаются буллеты
- Простые списки
```

### 5. columns — Колонки (2-3)

```markdown
# columns: 2
## Цели и задачи

### Цель
Текст первой колонки

### Ключевые задачи
Текст второй колонки
```

Число после `:` — количество колонок.

Дополнительно для отчетных слайдов: если указан `# columns: 2` или `# columns: 3`, но в контенте нет `###`-подзаголовков, а есть единый список (`1. ...` или `- ...`), генератор автоматически делит этот список по колонкам.

### 6. table — Таблица

```markdown
# table
## Технологический стек

| Технология | Преимущества |
| --- | --- |
| Nginx | Высокая производительность |
| Vue.js | Реактивность, Virtual DOM |
```

С боковой панелью (sidebar):

```markdown
# table: sidebar
## Предварительная стоимость проекта

| Этап | Стоимость |
| --- | --- |
| Аналитика | 630 000 |
| Дизайн | 2 108 000 |

---sidebar---
**Срок реализации**
~6,5-7 месяцев
```

### 7. steps — Этапы (до 9 пунктов)

Формат с `###` заголовками:

```markdown
# steps
## Порядок сотрудничества

### Формат работы
Описание этапа

### Сроки договора
Описание этапа

### Условия оплаты
Описание этапа

### Гарантия
Описание этапа
```

Или формат с нумерованным списком:

```markdown
# steps
## Порядок сотрудничества
1. Формат работы | Проект реализуется поэтапно.
2. Сроки договора | Согласование от 2 до 4 недель.
3. Условия оплаты | 50% предоплата и 50% после акта.
4. Гарантия | 6 месяцев на все работы.
```

Поддерживается до 9 элементов. 1-4: сетка 2×2, 5-6: сетка 3×2, 7-9: сетка 3×3.

### 8. case — Кейс

```markdown
# case
## Имед
**Компания:** Имед
**Описание:** Цифровой каталог медицинской техники
**Год:** 2025
**Категория:** Каталоги
- 12 тыс. | товаров в каталоге
- 80+ | параметров анализа
**Задачи:**
Перенести каталог на новую платформу.
**Теги:** Сайт
![screenshot](images/imed.png)
```

### 9. image — Слайд с изображением

```markdown
# image
## Архитектура
![architecture](images/architecture.png)
Подпись (опционально)
```

### 10. grid — Сетка карточек

```markdown
# grid: 3
## Ключевые метрики

### Утилизация
Доля оплачиваемых часов. Цель: 75–85%.

### КО
Выручка / ФОТ. Норма: 2,5×.

### Маржа
Цель: 50%+ валовая.
```

### 11. quote — Цитата

```markdown
# quote
##
Текст цитаты
— Автор цитаты
```

### 12. highlight — Акцент

```markdown
# highlight
## Заголовок
−321 000
Зарплата + налоги + косвенные. Всё ложится на другие проекты.
```

Первая строка содержимого — крупно по центру, остальное — мельче.

### 13. timeline — Таймлайн

```markdown
# timeline
## Сроки реализации

1. Аналитика | 4–6 нед. | Интервью, ТЗ
2. Дизайн | 6–8 нед. | UI Kit, макеты
3. Разработка | 10–12 нед. | Спринты
```

Формат: `N. Название | Срок | Описание`

### 14. contacts — Контакты

```markdown
# contacts
## Москва

**Email:** info@uplab.ru
**Phone:** +7 499 653 78 83
**City:** Москва
**Address:** 127055, ул. Новослободская, д. 61, стр. 2
**Site:** www.uplab.ru
```

### 15. toc — Содержание

```markdown
# toc
## Содержание
1. О компании
2. Цели и задачи
3. Технологический стек
4. Бюджет и сроки
5. Процессы
6. Кейсы
7. Команда
8. Контакты
```

До 5 пунктов — одна колонка, 6+ — автоматически 2 колонки. Номера показываются в формате 01, 02... по аналогии с дизайн-системой из Figma.

### 16. team — Команда

```markdown
# team
## Команда проекта

### Алексей Андреев
Руководитель проекта

### Дмитрий Глумов
Арт-директор
![photo](images/dmitry.png)

### Анастасия Букреева
Ведущий дизайнер
```

Автоматическая сетка: до 3 колонок × N рядов. Если указан путь к фото (`![photo](...)`) — вставляется изображение, иначе серый плейсхолдер.

## Логотип

На обложках и контактных слайдах автоматически вставляется логотип Uplab из `assets/logos/`. Для замены логотипа замените файлы `uplab_black.png` / `uplab_white.png`.

## Иконки

В папке `assets/icons/` доступны 31 "стеклянная" PNG-иконка (240×240) из дизайн-системы. Используйте их как изображения в grid, case и image слайдах:

```markdown
# grid: 3
## Наши услуги

### Разработка
![icon](assets/icons/site.png)

### Аналитика
![icon](assets/icons/240x240_search.png)
```

## Работа с изображениями

Формат: `![alt](путь/к/файлу.png)`

- Путь относительный (от рабочей директории) или абсолютный
- Если файл не найден — серый прямоугольник-плейсхолдер
- Рекомендуемый формат: PNG или JPEG
- Для кейсов: скриншот занимает правую половину слайда
- Рекомендуем создать папку `images/` и хранить изображения там

### Добавление изображений после генерации

1. Сгенерируйте презентацию (плейсхолдеры покажут, куда вставить картинки)
2. Откройте в Google Slides или PowerPoint
3. Кликните на серый прямоугольник → Удалить
4. Вставьте изображение → подгоните по размеру

## Google Slides workflow

### Генерация и импорт

1. Сгенерируйте PPTX:
  ```bash
   python generate.py content.md -o result.pptx
  ```
2. Загрузите `result.pptx` в Google Drive
3. Правый клик → «Открыть с помощью» → Google Slides
4. Проверьте визуальное качество

### Шрифт Inter

Шрифт Inter используется во всех презентациях Uplab. В Google Slides:

1. Откройте презентацию
2. Шрифты → Другие шрифты → найдите «Inter»
3. Добавьте Inter и Inter Medium

Если Inter не подключен, Google Slides заменит его на Arial.

### Что работает надёжно при импорте

- Текстбоксы с заливкой
- Таблицы (базовые стили)
- Автофигуры (прямоугольники)
- Изображения (PNG/JPEG)
- Заметки докладчика
- Нумерация слайдов

### Что может выглядеть иначе

- Тонкие границы таблиц
- Вертикальное выравнивание в ячейках
- Межстрочные интервалы

### Рекомендации

- Финальную корректировку делайте в Google Slides
- Не редактируйте PPTX в PowerPoint и затем импортируйте — лучше сразу в Google Slides
- Картинки вставляйте уже в Google Slides

## Масштабирование

Генератор автоматически масштабирует все элементы под размеры шаблона. Шаблоны с разными физическими размерами (10" vs 26.67" при одном ratio 16:9) будут выглядеть одинаково пропорционально.

## FAQ

**Q: Могу ли я использовать свой шаблон?**
A: Да, через `-t path/to/template.pptx`. Шаблон должен содержать хотя бы один layout. Рекомендуемые layout-имена: `BLANK`, `mint`, `gray`.

**Q: Как добавить новый тип слайда?**
A: Добавьте функцию `render_xxx` в `src/slide_types.py` и зарегистрируйте в `RENDERERS` в `src/engine.py`.

**Q: Текст обрезается / не помещается на слайде**
A: Сократите текст. Правило: не более 6-8 строк на текстовом слайде, не более 5-6 буллетов.

**Q: Как работают AI-агенты с этим инструментом?**
A: Агент (Cursor, ChatGPT) читает `AGENT_RULES.md`, генерирует content.md по описанию задачи, запускает `generate.py`. См. `AGENT_RULES.md`.
