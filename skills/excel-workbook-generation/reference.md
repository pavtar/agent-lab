# Справочник по генерации Excel-книг

Расширенная методичка (канон в репозитории):

```text
skills/excel-workbook-generation/guide/excel-workbook-generation-guide.md
```

Примеры книг: `skills/excel-workbook-generation/examples/`.

## Цель книги

Создать рабочий управленческий Excel-файл, а не CSV и не статичное описание таблицы. Книга должна быть полезна руководителям, менеджерам проектов, владельцам функций, командам исполнения и согласующим сторонам.

## Общие требования

- Формат файла: `.xlsx`.
- Файл должен открываться в Microsoft Excel и импортироваться в Google Sheets.
- Не использовать макросы.
- Не использовать внешние подключения и внешние ссылки.
- Не использовать сложные функции, которые могут некорректно открываться в Google Sheets.
- Использовать перенос текста.
- Задавать практичные ширины колонок.
- Задавать достаточную высоту строк для длинного текста.
- Закреплять строки заголовков на рабочих листах.
- Использовать цветные вкладки для навигации.
- Делать документ самодостаточным.

## Обязательный лист `i`

Первый лист должен называться `i`.

На нём нужно указать:

- название документа;
- назначение книги;
- целевых пользователей;
- когда использовать файл;
- краткое описание каждого листа;
- правила работы с книгой;
- кто обновляет файл;
- периодичность пересмотра;
- статусы, сокращения и обозначения;
- ответственные роли или контакты, если применимо.

## История версий

Лист `i` должен содержать раздел `История версий`.

Рекомендуемые колонки:

- `Версия`
- `Дата`
- `Автор / инициатор изменений`
- `Что изменилось`
- `Причина изменений`
- `Комментарий`

Для первой версии:

- `Версия`: `1.0`
- `Что изменилось`: `Создана первая версия документа`
- `Причина изменений`: `Первичная фиксация плана / запуск управления`
- `Комментарий`: `Сравнение с предыдущей версией неприменимо, так как это первая версия`

## Правила версионирования

При перегенерации или существенном обновлении книги:

- назначай новый номер версии в названии файла;
- версия в названии файла должна совпадать с актуальной версией на листе `i`;
- не сохраняй существенно изменённый файл под старым номером версии;
- оставляй предыдущий файл как архив, если пользователь явно не просит заменить его;
- добавляй новую строку в историю версий с кратким описанием изменений.

Примеры:

- `План проекта v1.0.xlsx`
- `План проекта v1.1.xlsx`
- `План проекта v2.0.xlsx`

## Базовые листы

### `План`

Используется для проектных планов, дорожных карт, планов запуска, планов изменений и операционного управления.

Рекомендуемые колонки:

- `#`
- `Раздел / Блок`
- `Задача`
- `Ответственный`
- `Участники`
- `Срок / Период`
- `Приоритет`
- `Статус`
- `Результат / Артефакт`
- `Комментарий`

### `RACI`

Используется, если в задаче участвуют несколько ролей или команд.

Добавь расшифровку RACI:

- `R = Responsible`
- `A = Accountable`
- `C = Consulted`
- `I = Informed`

### `Риски`

Используется как реестр рисков.

Рекомендуемые колонки:

- `#`
- `Риск`
- `Вероятность`
- `Влияние`
- `Уровень`
- `Митигирующее действие`
- `Владелец`
- `Статус`

### `Приемка`

Используется для критериев готовности или приёмки.

Рекомендуемые колонки:

- `#`
- `Критерий готовности`
- `Как проверить`
- `Статус`
- `Комментарий`

## Чек-лист проверки

Перед завершением:

- Файл существует.
- Файл открывается через `openpyxl` или другой `.xlsx` reader.
- Первый лист называется `i`.
- Заявленные листы существуют.
- История версий есть.
- Актуальная версия указана на листе `i`.
- Макросы и внешние ссылки намеренно не добавлялись.
- Длинный текст читается.
