# Справочник по Toyota Kata Coaching

## Зачем нужен skill

Toyota Kata — это практика развития научного мышления в управлении. Она полезна, когда руководитель хочет не просто дать сотруднику совет, а научить его самостоятельно ставить цель, видеть факты, выбирать препятствие и проводить короткие эксперименты.

Подробная база знаний для руководителей находится в `knowledge/toyota-kata/`.

Карта исходных PDF и Markdown-выжимек находится в `knowledge/toyota-kata/00-source-map.md`.

## Две части методики

### Improvement Kata

Improvement Kata описывает, как двигаться к улучшению:

1. `Challenge` — долгосрочный вызов или направление.
2. `Current condition` — текущее состояние, описанное фактами.
3. `Target condition` — ближайшее целевое состояние, которого нужно достичь.
4. `Experiments` — короткие шаги через препятствия с проверкой ожиданий.

### Coaching Kata

Coaching Kata — способ, которым руководитель развивает мышление другого человека. Руководитель задаёт вопросы и помогает ученику сделать мышление видимым.

## 5 вопросов коучинга

1. Каким является целевое состояние?
2. Каким является фактическое состояние в данный момент?
3. Какие препятствия мешают достичь целевого состояния? Каким именно препятствием ученик будет заниматься сейчас?
4. Каким будет следующий шаг или эксперимент? Чего ученик ожидает?
5. Когда мы сможем пойти и увидеть, что изучили в результате выполнения этого шага?

Если был предыдущий шаг, сначала отрази его: что планировали, чего ожидали, что случилось, чему научились.

Для новичков важно не отходить от сценария 5 вопросов слишком рано. Уточняющие вопросы допустимы, но они нужны для понимания мышления ученика, а не для проталкивания решения коуча.

## Первый сценарий: тренажёр руководителя

Цель сценария — тренировать руководителя задавать сильные коучинговые вопросы.

Цикл тренировки:

1. Агент даёт короткую управленческую ситуацию.
2. Руководитель формулирует вопрос, который задал бы сотруднику.
3. Агент оценивает вопрос по критериям ниже.
4. Агент показывает, где вопрос превращается в совет или давление.
5. Агент предлагает более сильную формулировку.
6. Цикл повторяется 3-5 раз.

## Критерии хорошего вопроса

Хороший вопрос:

- помогает человеку самому увидеть факты;
- связан с target condition или current condition;
- не содержит готового решения;
- не обвиняет и не защищает позицию руководителя;
- помогает выбрать одно препятствие или следующий эксперимент;
- приводит к проверяемому действию и обучению.

Слабый вопрос:

- содержит скрытый приказ: "Почему ты не сделал X?";
- подсказывает решение: "Может, тебе просто надо сделать Y?";
- слишком широкий: "Что вообще происходит?";
- оценивает человека вместо процесса;
- перескакивает к действиям без current condition;
- требует отчёта, но не развивает мышление.

## Примеры

Слабый вопрос:

```text
Почему вы до сих пор не исправили процесс продаж?
```

Лучше:

```text
Какое текущее состояние процесса продаж мы видим на фактах?
```

Слабый вопрос:

```text
Может, вам нужно просто быстрее отвечать клиентам?
```

Лучше:

```text
Какое препятствие сейчас сильнее всего мешает нам достичь целевого времени ответа?
```

Слабый вопрос:

```text
Когда уже будет результат?
```

Лучше:

```text
Какой следующий эксперимент мы можем провести и когда посмотрим, чему он нас научил?
```

## Остальные сценарии агента

### kata_assistant

Справочный сценарий по всей Toyota Kata для начинающих руководителей. Используется, когда пользователь задаёт методологический вопрос, путается в терминах или не знает, какой сценарий выбрать.

Формат ответа:

- короткий ответ на вопрос;
- простое объяснение через Toyota Kata;
- что важно не перепутать;
- какой сценарий использовать дальше;
- какие файлы базы знаний прочитать.

`kata_assistant` не подменяет практические сценарии. Если пользователь хочет тренировку, еженедельную сессию, разбор проблемы или внедрение в команду, нужно предложить соответствующий сценарий.

Подробности см. в `knowledge/toyota-kata/09-kata-assistant.md`.

### weekly_coaching

Еженедельная сессия по 5 вопросам для реальности Uplab. Результат: отражение прошлого шага, обновлённое текущее состояние, одно препятствие в работе, следующий эксперимент, ожидание и срок проверки.

Недельный цикл:

1. До встречи ученик обновляет Карту событий.
2. Коуч начинает с отражения прошлого шага: что планировали, чего ожидали, что случилось, чему научились.
3. Затем проходит 5 вопросов.
4. На неделю выбирается один следующий эксперимент или наблюдение.
5. Фиксируется дата проверки результата.

### problem_improvement

Разбор конкретной бизнес-проблемы через Toyota Kata. Результат сценария — Markdown Problem Improvement Canvas, который помогает не перепрыгивать к готовому решению.

Обязательные блоки:

- краткое описание бизнес-проблемы;
- challenge или направление;
- current condition: факты, метрики, наблюдения, неизвестные зоны;
- target condition: ближайшее целевое состояние;
- obstacles: список препятствий;
- one obstacle now: одно препятствие в работе;
- next experiment: гипотеза, шаг, ожидаемый результат, срок проверки;
- что нужно узнать до следующего цикла;
- риски преждевременного перехода к решению.

Если пользователь начинает с решения, сначала верни его к current condition и target condition.

Подробности см. в `knowledge/toyota-kata/08-problem-improvement.md`.

### team_playbook

Инструкция для команды, как встроить Toyota Kata в регулярный менеджмент: роли, недельный ритм, артефакты, первый пилот, риски и критерии успеха.

Результат сценария — Markdown-playbook для конкретной команды, а не универсальная методичка.

Обязательные блоки:

- цель внедрения;
- команда, процесс и границы пилота;
- роли: sponsor, coach, learner, second coach;
- ритм на 4-6 недель;
- артефакты: Карта событий ученика, PDCA, список препятствий;
- правила еженедельной сессии;
- первый пилот и критерии успеха;
- риски внедрения;
- действия на ближайшую неделю.

Подробности см. в `knowledge/toyota-kata/07-team-playbook.md`.

## Что агент не должен делать

- Не должен выдавать Toyota Kata как мотивационную лекцию без практики.
- Не должен решать проблему за пользователя.
- Не должен превращать коучинг в список поручений.
- Не должен давать длинную теорию, если пользователь находится в тренировочном цикле.
- Не должен продолжать без target condition, current condition или следующего эксперимента, если они нужны для сценария.
