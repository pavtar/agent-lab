# Бизнес-процессы для агента process-architect

База знаний по бизнес-процессам. Используется агентом `process-architect` и руководителями Uplab, которые хотят системно работать с процессами и потоками ценности.

## Источники

Исходные книги хранятся внутри проекта:

```text
knowledge/business-processes/sources/Менеджмент процессов.pdf
knowledge/business-processes/sources/Ротер. Учитесь видеть бизнес-процессы.fb2.epub
```

Это две разные методологии:

- "Менеджмент процессов" под ред. Й. Беккера и др. — BPM-подход к моделированию офисных и сервисных процессов: подготовка, "как есть", "как должно быть", оргструктура, внедрение.
- М. Ротер, Дж. Шук "Учитесь видеть бизнес-процессы" — Value Stream Mapping: карты материальных и информационных потоков, бережливый поток создания ценности.

Markdown-файлы в этой папке — рабочая выжимка для применения в компании.

## Как читать

1. [00-source-map.md](00-source-map.md) — карта источников и какие Markdown-файлы их покрывают.
2. [10-bpm-overview.md](10-bpm-overview.md) — обзор BPM-подхода Беккера: процессный vs функциональный, цикл реорганизации.
3. [11-bpm-as-is-modeling.md](11-bpm-as-is-modeling.md) — модель "как есть": подготовка, документация, анализ слабых мест.
4. [12-bpm-to-be-modeling.md](12-bpm-to-be-modeling.md) — модель "как должно быть": цели, детализация, целостная схема, внедрение.
5. [20-vsm-overview.md](20-vsm-overview.md) — VSM по Ротеру: для чего, основные принципы, отличия от BPM.
6. [21-vsm-current-state.md](21-vsm-current-state.md) — карта текущего состояния потока ценности: символы, метрики, потери.
7. [22-vsm-future-state.md](22-vsm-future-state.md) — карта будущего состояния и план перехода.
8. [30-uplab-vsm-level1-custom-dev-design.md](30-uplab-vsm-level1-custom-dev-design.md) — **корпоративная** карта потока ценности Uplab (уровень 1: заказная разработка и дизайн), синхронизированная с SSOT; это не методичка Ротера, а общий язык этапов и типовых потерь компании.

## Как выбрать сценарий агента

| Если нужно | Используйте сценарий |
| --- | --- |
| Сориентироваться, какой подход подходит | `process_assistant` |
| Быстро оценить процесс перед моделированием | `process_assessment` |
| Описать офисный или сервисный процесс по BPM | `as_is_map` |
| Описать сквозной поток ценности до клиента | `value_stream_map` |
| Спроектировать целевое состояние и план перехода | `to_be_design` |

## Принцип

Карта процесса — не самоцель. Она нужна, чтобы увидеть, где теряется ценность, и спланировать конкретные улучшения. Документировать стоит ровно столько, сколько нужно для принятия управленческого решения.
